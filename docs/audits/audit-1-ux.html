Executive Decision

The update fixed several earlier defects, including the deceptive-bid KPI, leveling-adjustment persistence, realtime package propagation, and the full autonomous lifecycle. It still fails the stated production bar because high-consequence records can be misidentified, unsupported files can enter the system as blueprints, an AI clarification can become addendum-approved without PM certification, and the built-in benchmark reports PASS while displaying a $4,000 ground-truth variance.

Recommended decision: do not use for live procurement, contract execution, or binding addenda until all P1 findings below are fixed and covered by automated regression tests.

P1 Findings

P1 / contract safety

Generated contracts still name the wrong prime contractor

Reproduction: the clean seeded project identifies Austin Commercial, LP in the project workflow, but the Contracts Register and AIA viewer name the contractor as Apex Commercial General Contractors LLC while the subcontractor is Rosendin Electric, Inc. Signing the agreement succeeds and marks it legally executed, so the identity error is not a harmless preview defect.

Source evidence: convex/agreements.ts:47 hard-codes const generalContractor = "Apex Commercial General Contractors LLC".

Fix: derive the prime contractor from the canonical project record, validate all parties before generation and signing, and block execution when project, GC, subcontractor, scope, amount, and contact identity do not reconcile.

P1 / file safety

Unsupported files are stored and misclassified as blueprints

Reproduction: uploading a harmless qa-invalid.exe was accepted despite the UI claiming PDF, DWG, DXF, and TXT support. It appeared in the document register as BLUEPRINT with Preview and Download actions. The file input still exposes an empty accept attribute.

Source evidence: src/components/ProjectFilesView.tsx:71-97 classifies by filename and falls back to the selected type, while convex/files.ts:21-40 accepts a free-form fileType without an extension or MIME allow-list.

Fix: enforce extension, MIME, size, and content validation on both client and server. Reject unsupported files before storage and never allow an unknown binary to enter AI or document workflows as a blueprint.

P1 / legal workflow

High-confidence manual RFIs bypass the stated PM certification gate

Reproduction: a manually submitted RFI received 96% confidence and immediately displayed Approved for Addendum with only Edit Response available. It was included in the generated Legal Addendum. The page says PMs review and certify before binding addenda, but the high-confidence path does not expose Approve or Reject controls.

Source evidence: convex/emailActions.ts:219-221 sends confidence scores below 0.92 to PM review and marks higher scores clarified; src/App.tsx:1062-1086 gives simulated/manual clarification a 0.95 score.

Fix: make PM certification mandatory for every binding addendum. AI confidence may prioritize the queue, but it must not change legal status without a recorded human approval.

P1 / evaluation integrity

Evaluation headline metrics contradict the visible case result

Reproduction: the live 10-case run completed and reported 10 / 10, 0.00% MAPE, and 100% scope recall. The visible case case-mep-02-scope-voids simultaneously showed Expert Ground Truth $46,500, AI Output $50,500, Delta +$4,000, and PASS.

Source evidence: convex/evals.ts:555-565 defines a 46,500 void target and computes the delta, while the UI still presents the contradictory PASS and zero aggregate error.

Fix: compute aggregate metrics from the displayed case metrics, fail any non-zero variance outside tolerance, and add a regression test for the cross-trade scope-void case.

P1 / bid integrity

Repeating quote extraction duplicates the same proposal

Reproduction: running Extract & Level Bid twice on the same Alterman_Power_Quote_Proposal.pdf produced two Alterman proposals in the leveling matrix: one $1,250,000 complete bid and the original $1,100,000 deceptive bid. There was no idempotency warning, source-file duplicate check, or replacement prompt.

Fix: persist the source file and extraction version on each proposal, enforce a uniqueness policy per package and source file, and require explicit “replace” or “create revision” intent before a second extraction.

P2 Findings

P2 / document trust

Generated addenda still show a placeholder preview and PDF label

The generated ADDENDUM_NO._01_CLARIFICATIONS.md appeared in storage, but Preview showed only an archive placeholder instead of the addendum content and the modal button still said Download PDF for a Markdown file. Genuine blueprint and quote previews did show real document text, so the behavior is inconsistent by file type.

Fix: show the stored text for Markdown/TXT files, label the action with the actual format, and expose parser/source status instead of claiming an authentic preview for fallback content.

P2 / operation feedback

Forensic clash scan takes about one minute with no completion result

Run Forensic Clash Scan stayed on “Scanning Cross-Trade Specs...” for roughly 60 seconds. It eventually completed, but there was no visible completion message, elapsed time, result delta, retry state, or audit confirmation in the view. A production operator cannot distinguish a slow valid run from a stuck one.

Fix: expose staged progress, elapsed time, cancellation, timeout/retry behavior, and a final result summary tied to the audit event.

P2 / project hygiene

Projects still have no archive or delete action

The selector still contains QA Test Tower - Temporary Audit from prior testing. New Project has no archive, delete, or undo control, and Reset Demo Data only resets the seeded Austin project. A production workspace cannot remove test or retired projects through the visible UI.

P2 / persistence

Selected project still resets to the seeded project after reload

Selecting the existing QA project and reloading returned to The Domain Tower B. The fallback is silent. Project context is high consequence because downstream packages, RFIs, bids, documents, and agreements are project-scoped.

Fix: persist the selected project per workspace and show an explicit fallback when it is unavailable.

P2 / audit correctness

File deletion is logged with the FILE UPLOADED event type

After deleting the unsupported test file, the Audit Stream displayed “File Deleted: qa-invalid.exe” under FILE UPLOADED. The description was correct, but the event category was not. This undermines filtering, reporting, and incident reconstruction.

Source evidence: convex/files.ts:167-175 inserts eventType: "file_uploaded" for deletion.

P2 / destructive UX

Destructive actions still depend on browser-native confirmation

Package and proposal deletion use blocking window.confirm dialogs. The action works, but the prompt has no in-app context, consequence summary, accessible focus management, or undo. The source uses this directly in src/components/TradePackagesView.tsx:382 and src/components/BidLevelingMatrixView.tsx:233.

P2 / domain validation

Package inputs still lack business constraints

CSI division, budget, and bid deadline fields have required validation but no min, max, pattern, or date bounds. Negative budgets, malformed division identifiers, and past deadlines remain client-accepted input shapes.

P2 / responsive workflow

Mobile navigation remains horizontally clipped

At a 390px mobile check, the header and navigation overflow horizontally. Only the first navigation items are visible and the rest require undiscoverable horizontal scrolling. Core sections can be missed on a phone-sized viewport.

Verified Improvements

Fixed since the previous audit

  • Dashboard now shows DECEPTIVE BIDS FLAGGED 1 for the seeded deceptive proposal.
  • Leveling adjustments saved to the database and survived reload; a $1,000 test adjustment remained $1,226,000 after reload.
  • Creating and deleting a package propagated to a second tab without reload.
  • Project-scoped subscriptions did not leak a main-project package into the QA project.
  • Authentic quote extraction produced structured exclusions and normalized costs.
  • One-click full lifecycle completed through RFQ, RFI, leveling, award, and AIA execution.

Positive production signals

  • Firecrawl discovery added verified contractors and profile scraping returned live parsed content.
  • Required form validation worked for project, contractor, package, and RFI forms.
  • Clash deductions and scope assignments persisted and updated the visible state.
  • Reset Demo Data restored the seeded Austin project after destructive testing.
  • Health, manifest, and webhook endpoints returned expected responses.
  • Unsigned webhook POSTs were rejected with HTTP 401 while GET status remained available.

Release Gate

Must fix before production use

  • Canonical project and contract-party identity.
  • Server-enforced file type/content validation.
  • Mandatory PM approval before binding addenda.
  • Evaluation metric and case-status reconciliation.
  • Idempotent quote extraction and proposal revisions.

Should fix before broad rollout

  • Real document previews and format-correct downloads.
  • Observable progress and completion for long scans.
  • Project archive/delete and selected-project persistence.
  • Correct audit event taxonomy.
  • Accessible confirmations, domain validation, and mobile navigation.
Final conclusion: the updated deployment is a credible functional prototype with several real production mechanisms. It is not yet production-grade for commercial procurement because the remaining failures affect legal identity, document trust, human approval, benchmark truth, and financial proposal integrity.
