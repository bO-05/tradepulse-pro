PARTLY → YES
Before: a GC's own proposal could be mis-priced — the lead-time penalty trusted model arithmetic (audit runs showed $0 / +$6,000 / +$24,000 for near-identical input) and per-exclusion pricing could substitute benchmarks or fabricated contacts. After: every ADR-0003 term is computed in code from the raw text and persisted per bid — lead weeks + target + arithmetic rendered, stated exclusion amounts bound positionally, unpriced scopes benchmarked by division, COI deficiency a deterministic $15,000 in both directions, VE/waivers GC-controlled; identical input twice is byte-identical live; the A401-style draft carries the GC's own identity and the contractor's own (or honestly unpublished) contact.
Core-claim fix (A6-05r / A6-54). The penalty is now max(0, weeks − baseline) × $6,000 computed in code, with the baseline pinned per division (Div 26: 12 wks; Div 22/23: 16 wks), persisted as leadTimeTargetWeeks, and rendered as arithmetic on every leveling surface: e.g. Lead Time (17 wks vs 16-wk baseline): (17 − 16) × $6,000 = +$6,000. The model no longer returns a dollar penalty. Live verification: identical text twice → identical persisted projection (sha1-verified across repeated ingests per division).
Verification correction (reproduced before believing the audit). AUDIT-6's "nondeterministic penalty" did not reproduce in 2026-09-21 trials: 8 controlled live ingests (Div 22 N=12/16/17/20 + Div 26 N=16) were internally consistent and matched the app's own per-division rule. The reproduced defects were structural: a stochastic model computing money, no visible baseline, and docs implying a universal 12-week target. A6-54's "$30,000" expectation assumed a 12-week baseline on a Div 22 package; under the documented 16-week Div 22 baseline the engine's +$6,000 was already correct. The audit's finding is therefore marked REPRODUCED (structural) / NON-DETERMINISM NOT RE-REPRODUCED and the baseline decision is documented in §5.

5 · Decisions (explicit, per the handoff's NEEDS-DECISION list)

D1 — Lead-time baseline target weeks. Chosen: GC-owned division milestones (Div 26: 12 weeks; Div 22/23: 16 weeks), centralized in convex/terms.ts, persisted per bid as leadTimeTargetWeeks, and rendered with the arithmetic and the baseline label. Rationale: the target is a GC schedule requirement, not a bidder claim; trusting a proposal-stated target would let a bidder lower their own penalty. Alternatives: (a) proposal-stated target — rejected (bidder-controlled, and the cause of audit-6's $30k-vs-$6k confusion); (b) a per-package target field editable by the GC — recommended future enhancement, not built in this pass (would need a tradePackages field + UI). Overrule path: the GC can adjust any penalty directly in "Adjust Leveling".
D2 — Judge Dock on custom projects. Kept as labeled theater with fixed demonstration figures (by design per the audit's protect list); the normal Award path derives the GC from the project record. Documented: the dock's confirm dialog and "fixed demonstration figures" disclosure stay.
D3 — Retainage / LD. 10% retainage and $1,200/day LD remain the single source in convex/terms.ts; only stale docs prose changed. A per-project terms editor is a NEEDS-DECISION product item.
D4 — VE accept / waive defaults. Ingested VE alternates default to not accepted and ingested exclusions default to not waived; both are explicit GC toggles in the adjustment panel (now proven to save correctly, including HTTP). Add-alternates remain unrepresentable (the schema models deduct credits only); a stated "add $X" is recorded with 0 impact rather than corrupting totals. Options: add a costAdd field + formula/UI (medium change) or document the limitation — recommended follow-up, not done here to keep diffs surgical.
D5 — Demo data carried over. Per the operator's "demo project untouched and byte-stable" rule, three stale seeded artifacts were deliberately not rewritten (documented in §9): the stored demo agreement text (predates the A401-style generator), the demo's seeded "Active / Verified (TDLR/TSBPE)" license labels, and historical seeded audit rows about AgentMail/TDLR. The seed code was corrected so any re-seed produces honest labels/text, and a one-command re-seed (projects.seedInitialData({force:true})) would refresh the stored copies if the operator wants it.

9 · Honesty section

Could not be tested: true external AgentMail send/receive at the provider (the app-level result is 0 delivered on every attempt; the root cause is provider-side — inbox 404 / plan limit — and was not changed; no secrets were read or set); multi-user concurrency beyond two browser contexts; auth/identity/isolation (explicitly out of scope).

Anthropic temperature: the audit's fix list asked for temperature 0. OpenAI and Gemini calls now use temperature 0 (+ seed for OpenAI where supported); this Anthropic model rejects the deprecated temperature parameter with HTTP 400, so sending it would have silently killed the live model path (it did during one intermediate build). Determinism is therefore enforced in code — weekly/monthly lead parsing, penalty formula, exclusion pricing, COI, severity, waivers — and verified by repeated live ingests, not by decoding settings.

Carried LOW findings (non-blocking): the COI text rule does not yet recognize the "statutory workers' compensation and employers liability coverage only" phrasing (the model catches it live); and model exclusion descriptions can be rephrased between identical ingests while every numeric field stays byte-identical.

Demo data deliberately not rewritten (D5): the seeded demo agreement still carries its pre-remediation official-form title/body; the live demo's seeded license labels read "Active / Verified (TDLR/TSBPE)"; and historical seeded audit rows still reference registry verification and AgentMail dispatch. These are stale fixtures, not current code paths (the generators are honest); the operator's byte-stability rule was honored, and the seed code is fixed for future re-seeds.

Fixtures: every test fixture was named AUDIT7-* (or the harness's AUDIT-QA-SMOKE-*) and deleted; one accidental probe contractor added to the demo during round 12 was removed within the same round and the demo counts re-verified (one "Contractor Removed" audit entry remains as the trace). Final Projects list: only "The Domain Tower B - Commercial MEP"; the demo headline numbers are unchanged across every round.

Deployment basis: the fixes were deployed to the project's production deployment (brainy-skunk-440) — schema + functions via npx convex deploy and the static frontend via the mounted static-hosting component — because the mission requires live-app verification. No deployment environment variables or keys were changed.

Raw evidence: every JSON/PNG/CSV cited above lives in the git-ignored evidence/ directory (fix6-* and conv-r*-* artifacts) plus the harness scripts under scripts/audit7/.
